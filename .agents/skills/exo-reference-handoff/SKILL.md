# EXO reference handoff

Locate the repository containing docs/FIRST-PLAYABLE-PRODUCTION.md; do not assume the neighboring original checkout is current.

Read docs/FIRST-PLAYABLE-PRODUCTION.md and assets/reference/first-playable/manifest.json first. The complete destination remains docs/GAME-VISION.md; detailed proposals live in GAME-DESIGN-EXPANDED.md.

For art/reference requests:
- Use the current image-generation skill and the locked original Vanguard sheet. Never regenerate or overwrite the anchor unless Ash requests that change.
- Preserve originals, exact prompts, source paths and hashes, attempts, acceptance reasons and unresolved contradictions.
- Neutral construction views outrank action/scenery panels. Major left/right or attachment contradictions require a correction or an explicitly bounded incomplete status.
- A sheet may cover multiple buildable objects; retain constituent IDs, roles and relative scales.
- Reference acceptance is not model, animation, gameplay or user acceptance.
- Stop at the requested preparation boundary; a dormant implementation brief is not authorization to run it.

For authorized implementation:
- Read docs/FIRST-PLAYABLE-IMPLEMENTATION-HANDOFF.md and docs/MODEL-VIEWER.md.
- Read the current /Users/ash/.img2/SETUP-LOCAL.md and symlinked img2threejs skill; do not copy that pipeline into this skill.
- Use the moving-character profile where required, preserve state/evidence gates, reuse existing viewer surfaces and check the actual game route.
- Reconcile current Vanguard representations by evidence; old docs differ and the showcase has a TRELLIS-derived surface example. Do not label it a verified pure procedural construction.
- Keep weapon grips, anatomical sides, scale and simulation contact coherent. Catalog references are not single-object solver inputs.
- Keep detailed procedures and balance proposals in repository docs, not duplicate copies here.
